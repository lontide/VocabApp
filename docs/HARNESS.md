# VocabApp 검증 Harness

기능·데이터 계약은 [SPEC.md](../SPEC.md), 알려진 결함과 후속 작업은 [TASKS.md](../TASKS.md), 작업 규칙은 [AGENTS.md](../AGENTS.md)를 참조한다. 이 문서는 실행 및 검증 절차만 관리한다.

## 실행

Node.js 24(CI와 동일)와 npm을 사용한다.

~~~sh
npm ci
npm run check
npm run dev
~~~

- npm test: Node 내장 러너가 tests/*.test.mjs를 실행한다. 기존 TypeScript 의존성으로 유틸리티를 메모리에서 변환하며 별도 테스트 프레임워크는 없다.
- npm run check: 자동 테스트 → TypeScript 검사 → Vite 프로덕션 빌드. 어느 단계든 실패하면 중단한다.
- npm run preview: 빌드한 dist를 로컬에서 확인한다. 하위 경로 배포 검증은 실제 해당 경로 환경에서도 수행한다.
- .github/workflows/check.yml: PR 및 main/master push 검증. deploy.yml: main/master push 또는 수동 실행에서 같은 검증 후 Pages 배포.
- 문서만 바꾸면 관련 소스·상대 링크·명령·git diff --check를 확인한다. 앱 테스트를 다시 실행했다고 기록하지 않는다.

## 자동 검증 범위

| 테스트 | 확인하는 계약 |
| --- | --- |
| tests/quiz-data.test.mjs — 데이터 | 2,500개 표현, 50개 탄, 고유 정수 ID, 필수 학습 텍스트, 탄별 개수·ID·카테고리 대응 |
| tests/quiz-data.test.mjs — 퀴즈 | 4개 모드의 질문·정답·TTS 텍스트 매핑, 정답 1개, 후보 제외 규칙, 셔플 입력 보존, 작은 풀·중복 오답의 현재 동작 |
| tests/storage.test.mjs | 기본값, 저장/읽기 왕복, 일부 잘못된 값·JSON 파싱 실패·저장소 접근 거부 |
| npm run build | strict TypeScript 검사와 프로덕션 번들 생성 |

퀴즈 검사는 실제 데이터를 사용하지만 모든 오답 풀 조합과 무작위 분포를 검증하지 않는다. 저장소 검사는 모든 스키마 손상을 다루지 않는다. DOM·Hook 호출 순서·브라우저 상호작용·실제 발음·설치·배포 성공은 이 자동 검사로 증명하지 못한다. 테스트가 통과해도 TASKS.md의 알려진 결함은 남을 수 있다.

## 수동 스모크 시나리오

검사 전 브라우저·기기·실행 주소·대상 커밋을 기록한다. 초기 상태는 전용 브라우저 프로필이나 해당 사이트 저장소만 초기화해 준비한다.

| ID | 시나리오와 기대 결과 |
| --- | --- |
| M-01 | 데스크톱·모바일 폭에서 초기 1탄 카드와 진행을 확인한다. 가로 넘침·버튼 가림이 없어야 한다. |
| M-02 | 개별·구간·전체 탄 선택을 적용하고 덱 개수와 진행 초기화를 확인한다. 마지막 탄 해제를 막고 새로고침 후 선택을 보존해야 한다. 취소→재개방도 확인한다(T-04). |
| M-03 | 4개 모드에서 SPEC의 질문/정답 매핑과 카드 앞·뒤, 예문을 확인한다. Space 뒤집기, 오른쪽 평가, 왼쪽 이전/첫 카드 오답 처리, R 발음을 확인한다. |
| M-04 | 객관식 1~4 선택, 정오답 피드백, 추가 선택 차단, Enter/Space/오른쪽 다음 이동, 점수·연속 정답을 확인한다. |
| M-05 | 이전 카드 재평가 및 같은 문항의 모드·스타일 전환 후 재응답에서 점수 중복을 확인한다. 결함은 T-03으로 추적한다. |
| M-06 | 한 탄을 완료하고 결과·전체 재시도·오답만 재시도를 확인한다. 재시도와 셔플에서 진행이 초기화되며 새로고침 후 세션 오답은 유지되지 않는다. |
| M-07 | 사전을 열고 닫고 다시 연다. 선택 탄/전체/북마크 검색, 50개 더 보기, 북마크 추가·해제와 새로고침 보존을 확인한다. 우선 T-01 Hook 오류 수정 여부를 확인한다. |
| M-08 | 각 모달의 입력·버튼에 포커스를 두고 단축키를 눌러 배경 진행이 바뀌는지 확인한다(T-05). 키보드 탐색·닫기·포커스 복원도 기록한다. |
| M-09 | TTS 지원 환경에서 단어·예문을 듣고, 미지원 환경에서는 재생 요청으로 앱이 중단되지 않는지 확인한다. |
| M-10 | QR·표시 주소·복사 결과가 일치하고 실제 휴대폰에서 앱이 열리는지 확인한다. LAN 주소와 Pages 하위 경로를 각각 검사한다. 현재 고정 IP·경로 누락은 T-02로 추적한다. |
| M-11 | preview와 배포 하위 경로에서 자산·아이콘을 확인한다. 설치 이벤트 지원/미지원 시 설치 창 또는 안내, standalone 배너 숨김을 확인한다. 오프라인 동작은 합격 조건이 아니다. |

## 결과 기록

각 검증 작업이나 PR에 환경, 대상 커밋, 실행 명령과 성공/실패, 수동 시나리오 ID별 결과를 기록한다. 실패·차단은 관련 TASK ID에 연결하고 미실행은 미실행으로 적는다. 기존 자동 테스트 통과 기록을 브라우저 검증 완료로 대체하지 않는다.
