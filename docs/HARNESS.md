# 현재 구현 기준 Harness

## 실행
Node.js 24(CI와 동일) 및 npm을 사용한다.

```sh
npm ci
npm run check
npm run dev
```

`npm test`는 Node 내장 테스트 러너와 기존 TypeScript 의존성으로 유틸리티를 메모리에서 변환하여 실행한다. 별도 테스트 프레임워크나 생성 파일이 없다. `npm run check`는 테스트 이후 TypeScript 검사 및 Vite 프로덕션 빌드를 수행한다. PR과 main/master push에서 CI가 같은 명령을 실행한다.

## 구현 상태
| 영역 | 현재 동작 | 검증 |
| --- | --- | --- |
| 데이터 | 50개 탄, 2,500개 표현, XLSX에서 JSON 생성 | 개수, 필수 학습 필드, ID, 탄별 역참조 자동 검사 |
| 학습 | 4개 모드, 플래시카드/객관식, 덱 셔플 | 모드별 질문/정답/TTS 및 선택지 계약 자동 검사 |
| 저장 | 선택 탄·모드·스타일·북마크 localStorage 저장 | 기본값, 왕복 저장, 파싱 실패 및 접근 거부 자동 검사 |
| 진행 | 점수·연속 정답·오답 재시도 | 브라우저 수동 검사; 세션 오답은 새로고침 시 소실 |
| 검색 | 전체 사전, 선택 탄/북마크 필터 | 브라우저 수동 검사 |
| 브라우저 기능 | TTS, QR 연결, 설치 배너와 manifest | 실제 기기 수동 검사; 서비스 워커 없음 |

## 수동 스모크 시나리오
- 데스크톱과 모바일 폭에서 초기 1탄 덱과 카드가 표시되는지 확인한다.
- 탄 선택에서 복수 탄을 적용한 뒤 덱 개수와 진행 초기화를 확인한다. 새로고침 후 선택이 유지되어야 한다.
- 4개 모드 각각에서 카드 앞/뒤의 질문·정답·예문을 확인한다. Space 뒤집기, 좌우 이동, R 발음을 확인한다.
- 퀴즈에서 1~4 선택, 정답/오답 피드백, 중복 제출 방지, Enter/Space 다음 문제, 점수와 연속 정답을 확인한다.
- 한 탄 학습을 완료하고 결과, 전체 재시도, 오답만 재시도를 확인한다. 셔플 시 진행과 오답이 초기화되어야 한다.
- 북마크를 추가/해제하고 검색·필터 및 새로고침 후 보존을 확인한다.
- 모달을 연 상태에서 검색 입력과 키보드가 배경 학습에 영향을 주는지 확인한다. 발견된 문제는 별도 수정 대상으로 기록한다.
- 발음 지원/미지원 브라우저에서 재생과 오류 여부를 확인한다. 음성 품질은 자동 검사 범위 밖이다.
- QR에 현재 접속 주소가 들어가는지 확인한다. 휴대폰에서 localhost는 PC 주소가 아니므로 접근 가능한 호스트로 접속한다.
- preview 빌드에서 아이콘과 정적 자산을 확인한다. 설치 가능 여부는 브라우저에 따라 다르며 오프라인 동작을 보장하지 않는다.

## 알려진 경계
- 객관식은 정답과 같은 텍스트를 오답에서 제외하지만 오답끼리 텍스트가 중복될 수 있다. 작은 풀에서는 선택지가 4개 미만이다. 현재 동작을 자동 테스트에 명시한다.
- 저장값의 모든 스키마를 검증하지 않는다(예: 북마크 JSON의 배열 여부). 손상된 저장소 전체 복구는 미구현이다.
- 플래시카드 이전 이동 후 재평가 시 점수 재계산, 모달 키보드 격리는 수동 확인 대상이다.
- 자동 검사는 DOM, 실제 브라우저 상호작용, TTS, 설치, 배포 성공을 증명하지 않는다.
